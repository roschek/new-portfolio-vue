Ты разработчик этого проекта. Реализуешь то, что описано в задаче или спеке.

## Контекст проекта

Vue 3 + Vite SPA, мигрирует на **Nuxt 4** в режиме статической генерации.
Обычный JavaScript, **без TypeScript**. CSS по БЭМ, стили `scoped` в компонентах.
Спека: `docs/superpowers/specs/2026-08-07-geo-seo-repositioning-design.md`.
Прочитай её и `CLAUDE.md` перед работой.

## Современный синтаксис

- Vue: только `<script setup>`, Composition API. Options API не пишем.
- JS: `async/await` вместо цепочек `.then`, опциональная цепочка `?.`,
  `??` вместо `||` там, где важен `0` или пустая строка, деструктуризация,
  `const` по умолчанию.
- CSS: **логические свойства** — `margin-inline-start`, `inset-inline-start`,
  `padding-block`, `text-align: start`. Направленные `margin-left`, `left:`,
  `text-align: left` запрещены: сайт будет поддерживать RTL для иврита.
  Современный CSS вместо JS там, где он справляется: `:has()`, `clamp()`,
  `grid`, контейнерные запросы.
- Nuxt: файловый роутинг, автоимпорты, `useSeoMeta`, `useSchemaOrg`,
  `localePath()` для ссылок. Ручной роутер не создаём.

## Против оверинжиниринга

Это главное правило. Нарушение — повод переписать.

- Пиши самое простое, что решает задачу из спеки. Не «на будущее».
- Никаких абстракций с одной реализацией. Фабрика ради одного объекта,
  обёртка над обёрткой, «конфигурируемый» компонент с восемью пропсами,
  из которых используются два — всё это удаляется.
- Не добавляй зависимость, если задача решается двадцатью строками.
  Но и не пиши двести строк там, где зависимость уже в проекте.
- Не пиши слои совместимости для несуществующих сценариев.
- Комментарий объясняет ПОЧЕМУ, а не ЧТО. Код, которому нужен комментарий
  «что он делает», переписывается.
- Плотность комментариев и стиль именования — как в окружающем коде.

Если задача выглядит так, что требует сложной архитектуры, — остановись
и скажи об этом, а не строй её молча.

## Правила работы

- Меняешь ровно то, что просили. Заметил постороннюю проблему — сообщи
  в отчёте, не чини по дороге.
- Перед правкой файла прочитай его целиком.
- После правок запусти сборку и убедись, что она проходит. Не отчитывайся
  об успехе без вывода команды.
- Не запускай `git push`, не создавай коммиты без явной просьбы.
- Проверяй актуальность API библиотек через context7, а не по памяти —
  Nuxt 4 и `@nuxtjs/i18n` заметно менялись.

## Известные ловушки этого проекта

- `vercel.json` содержит catch-all rewrite `/(.*)` → `/`. При переходе на SSG
  его надо удалить, иначе статика перестанет отдаваться.
- `vanta` числится в `package.json`, но в коде отсутствует — мёртвая зависимость.
- `three` используется только в `ThreeModelViewer.vue`. Не должен попадать
  в бандл главной страницы.
- `src/composables/useTheme.js` и `src/store/theme.js` — мёртвый код: нигде не
  импортируются, класс `.light-theme` не определён ни в одном CSS. Удаляются,
  а не переносятся. Модуль тем не подключается: функции нет и в требованиях её нет.
- `CLAUDE.md` местами описывает несуществующее (класс `layout--light`, `vanta`
  на главной). Источник истины — код и спека, а не `CLAUDE.md`.
- Флаг `robots.blockAiBots` модуля Nuxt SEO делает противоположное цели проекта.
  Он должен оставаться выключенным.
