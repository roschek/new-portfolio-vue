# Переводчик лекций (PWA) — спецификация

Дата: 2026-11-05. Статус: согласовано в брейншторме.
Вдохновение: Meetup Interpreter (alexeyabramov.com/translate).

## Цель

Приложение на маршруте `/translate` сайта: во время лекции показывает живой
перевод речи на выбранный язык, сохраняет расшифровку и по запросу делает
саммари. Ставится на телефон как PWA. Каждый пользователь работает со своими
ключами API, бэкенда нет.

## Ключевые решения

- **Ключи — пользователя.** Soniox для распознавания и перевода, плюс ключ
  одного из провайдеров саммари: Gemini, Anthropic или OpenAI. Ключи хранятся
  только в браузере и отправляются только своему провайдеру.
- **Маршрут внутри портфолио**, а не отдельное приложение. Код изолирован
  в `src/translate/`, чтобы при возможной миграции на Nuxt переехать целиком.
- **Движок — только Soniox**, напрямую из браузера по WebSocket через
  `@soniox/client`. OpenAI Realtime и Web Speech API отклонены:
  первый примерно в 10 раз дороже, второй плохо распознаёт иврит и не переводит.
- **Языки.** Язык речи определяется автоматически, лектор может переключаться
  между языками. Язык перевода выбирается из EN, HE, RU, DE, ES. Перевод
  односторонний (`translation.type: 'one_way'`).
- **Сохраняется текст, аудио — нет.**
- **Интерфейс на RU и EN**, выбирается по языку браузера. Языки перевода
  и языки интерфейса — разные списки.
- **Ограничение платформы:** при блокировке экрана или сворачивании браузер
  останавливает микрофон. Решения — Screen Wake Lock, автосохранение
  и продолжение прерванной записи. Запись с выключенным экраном не
  поддерживается.

## Экраны

Маршруты `/translate/*` рендерятся без шапки, футера и плавающей кнопки
контакта сайта: у маршрута `meta: { bare: true }`, `App.vue` по этому
флагу рендерит страницу без `DefaultLayout`. Вместо неё — компактная панель приложения со ссылкой
«← сайт».

1. **`/translate` — живой перевод.**
   - Сверху: язык перевода, размер текста, полноэкранный режим.
   - Перед стартом — необязательные поля «название лекции» и «тема/термины».
     Они уходят в Soniox как контекст.
   - Лента абзацев: перевод крупно, оригинал мелко и приглушённо (скрываемый).
     Нефинальные слова бледные, финальные — обычного цвета.
   - Внизу, в зоне большого пальца: кнопка записи и «Пауза / Продолжить».
   - Строка статуса моноширинным шрифтом:
     `● REC 01:12:40 · auto→RU · 9 418 слов`.
2. **`/translate/sessions` — библиотека.** Список лекций (название, дата,
   длительность, языки), поиск по тексту.
3. **`/translate/sessions/:id` — просмотр.** Вкладки «Перевод / Оригинал /
   Саммари». Экспорт, переименование, удаление.
4. **`/translate/settings` — ключи.** Поле Soniox и поле для ключа одного
   из провайдеров саммари (провайдер выбирается переключателем). Возле каждого
   ключа кнопка «проверить». Галочка «запомнить на устройстве»: включена —
   `localStorage`, выключена — `sessionStorage`. Кнопка «забыть ключи».

## Визуальный язык

- Берётся из токенов `src/assets/main.css`: `--bg`, `--accent`, `--text-*`,
  Syne, DM Sans, JetBrains Mono. Будущий редизайн сайта подхватится
  автоматически, своих цветов приложение не вводит.
- Редакционные детали: моноширинные метки и строка статуса, отметки времени
  на полях моноширинным шрифтом.
- Кнопка записи — круг цвета `--accent` с кольцом, пульсирующим от уровня
  громкости микрофона (AnalyserNode). Это обратная связь «микрофон слышит».
- Абзацы не шире 65 символов, новый абзац появляется с плавным проявлением.
  При `prefers-reduced-motion` анимации отключены.
- Только логические CSS-свойства, у текстовых блоков `dir="auto"` для иврита.
- БЭМ, стили `scoped`, как в остальном проекте.

## Архитектура

```
src/translate/
  pages/        LivePage.vue, SessionsPage.vue, SessionPage.vue, SettingsPage.vue
  components/   RecordButton.vue, TranscriptFeed.vue, StatusLine.vue, …
  composables/  useLiveSession.js
  services/
    sonioxStream.js
    transcriptBuilder.js
    sessionStore.js
    summarizer.js
    keyVault.js
  i18n.js
```

### Модули

- **`sonioxStream`** — единственный модуль, который знает о Soniox.
  - Вход: `{ key, targetLang, context }`.
  - Выход: события `tokens`, `state`, `error`, метод `stop()`.
  - Конфигурация: `translation: { type: 'one_way', target_language }`,
    `enable_endpoint_detection: true`,
    `context: { general: [{ key: 'topic', value }], terms }`.
  - Имя модели — одна константа.
- **`transcriptBuilder`** — чистые функции без зависимостей от браузера.
  - Склеивает токены с `translation_status: 'original' | 'translation'`
    в пары абзацев «оригинал ↔ перевод».
  - Режет на абзацы по маркеру конца фразы.
  - Проставляет `startMs` и язык абзаца.
  - Хранит отдельно финальные абзацы и текущий нефинальный хвост.
- **`useLiveSession`** — оркестратор:
  - связывает поток Soniox и сборщик расшифровки;
  - измеряет уровень микрофона;
  - держит Screen Wake Lock;
  - сохраняет лекцию каждые 5 секунд и на `visibilitychange`;
  - переподключается при обрывах;
  - отвечает за паузу и продолжение.

  Финализированные абзацы публикуются отдельным событием `paragraph`
  (см. «На будущее»).
- **`sessionStore`** — CRUD лекций в IndexedDB через `idb`.
- **`summarizer`** — `summarize({ provider, key, text, lang })` → Markdown.
  - Три адаптера, `fetch` прямо из браузера.
  - Для Anthropic нужен заголовок `anthropic-dangerous-direct-browser-access: true`.
  - Модели по умолчанию — быстрые и дешёвые (Gemini Flash, Claude Haiku,
    GPT mini), имена хранятся константами.
- **`keyVault`** — чтение, запись и удаление ключей, выбор между
  `localStorage` и `sessionStorage`.
- **`i18n.js`** — словарь строк RU/EN и функция `t(key)`.

### PWA

- `vite-plugin-pwa`, манифест и service worker со `scope: '/translate/'`,
  `start_url: '/translate/'` (со слешем — иначе start_url вне scope). Остальной сайт PWA не затрагивает.
- `<link rel="manifest">` подключается только на маршрутах `/translate/*`,
  чтобы браузер не предлагал установить главную страницу портфолио.
- Маршруты переводчика грузятся лениво (`() => import(...)`): посетители
  портфолио не скачивают SDK Soniox.
- Кэшируется оболочка приложения. Без сети работают библиотека и просмотр
  лекций, запись — нет.

### Новые зависимости

- `@soniox/client`
- `idb`
- `vite-plugin-pwa`
- `marked` и `DOMPurify` — для саммари. Markdown от модели перед `v-html`
  обязательно проходит через очистку.

## Данные

Одна запись IndexedDB на лекцию:

```js
{
  id, title, createdAt, durationMs,
  status: 'recording' | 'done',
  targetLang: 'ru',
  detectedLangs: ['he', 'en'],
  context: { topic, terms: [] },
  paragraphs: [{ startMs, lang, original, translation }],
  summary: null | { provider, model, markdown, createdAt }
}
```

- Полуторачасовая лекция весит примерно 300 КБ.
- Ключи в IndexedDB не хранятся.
- **Восстановление.** При открытии приложения ищется лекция со статусом
  `recording`, которая сейчас не пишется. Если такая есть — плашка
  «Запись прервалась на MM:SS — продолжить?». Продолжение открывает новое
  соединение Soniox и дописывает абзацы в ту же лекцию.

## Саммари

- В модель отправляется **оригинал**, а не перевод. Ответ — на языке перевода
  лекции.
- Структура ответа:
  1. суть в 3–5 предложений;
  2. ключевые тезисы;
  3. термины с оригинальным написанием;
  4. упомянутые задания и даты, если они есть.
- Лекция отправляется целиком, без нарезки.
- Перед запуском показывается примерное число токенов.
- Результат сохраняется в лекции, есть кнопка «Пересоздать».

## Экспорт

- Markdown: саммари и расшифровка с отметками времени.
- TXT.
- «Скопировать».
- «Поделиться» через Web Share API, если он доступен.

## Обработка ошибок

Сбой не должен стирать уже распознанный текст.

| Ситуация | Поведение |
|---|---|
| Нет ключа Soniox | Вместо кнопки записи — карточка настройки: ссылка на console.soniox.com и поле ключа |
| 401 или нет баланса | Запись останавливается, сообщение и ссылка в настройки |
| Микрофон запрещён | Инструкция для платформы: iOS Safari, Android Chrome, десктоп |
| Обрыв сети | Статус «переподключение», три попытки с нарастающей паузой. Если не удалось — пауза и «Продолжить». Финальные абзацы сохранены |
| Soniox закрыл сессию по лимиту длительности | Незаметное переподключение |
| Ошибка саммари (401, 429, сеть) | Сообщение и «Повторить», расшифровку не затрагивает |
| IndexedDB недоступна | Предупреждение «лекции не сохранятся», перевод работает |

## Тестирование

- В проект добавляется Vitest (окружение happy-dom).
- Порог покрытия — **70%**, считается только по `src/translate/services/`
  и `src/translate/composables/`. Компоненты и страницы проверяются вручную.
- Что покрывается:
  - **`transcriptBuilder`** — табличные тесты на реальные последовательности
    токенов: смешанные языки, паузы, замена нефинальных токенов.
  - **`sessionStore`** — с `fake-indexeddb`: создание, дописывание,
    восстановление прерванной записи.
  - **`summarizer`** — с подменённым `fetch`: запрос и разбор ответа у трёх
    провайдеров, обработка 401 и 429.
  - **`useLiveSession`** — с подменённым `sonioxStream`: переходы состояний,
    пауза и продолжение, переподключение, автосохранение.
- Ручной чек-лист на устройствах:
  - установка PWA на iOS Safari и Android Chrome;
  - 10 минут речи на иврите с переводом в RU;
  - блокировка экрана, затем восстановление записи;
  - режим полёта посреди записи;
  - саммари у каждого из трёх провайдеров.

## Вне объёма

- хранение аудио;
- разделение по спикерам;
- синхронизация между устройствами;
- иврит, немецкий и испанский в интерфейсе;
- редизайн сайта — отдельный цикл.

## На будущее: синхронный перевод голосом

Озвучка перевода в наушники, как у Meetup Interpreter. Сейчас не делается,
но архитектура к ней готова:

- `useLiveSession` публикует событие `paragraph` с финализированным абзацем
  перевода. Будущий модуль `speechOutput` подписывается на это событие
  и не трогает остальной код.
- **Движок — только нативный `speechSynthesis`.** Это голоса самой ОС
  телефона: бесплатно и без ключей. TTS провайдеров не используется.
  Голос выбирается из `speechSynthesis.getVoices()` по языку перевода.
  Если голоса для языка нет — озвучка для этого языка недоступна,
  с подсказкой, как установить голос в настройках ОС.
- **Только через наушники.** Так снимается проблема эха: озвучка не попадает
  обратно в микрофон. Браузер не умеет надёжно определять наушники
  (на iOS список устройств вывода недоступен), поэтому при включении озвучки
  пользователь подтверждает «я в наушниках». Без подтверждения озвучка
  не включается.
- Вопросы, которые нужно решить в отдельном цикле:
  - очередь и отставание озвучки от речи на длинных лекциях;
  - пропуск абзацев, если озвучка не успевает (например, озвучивать только
    последний абзац при отставании больше N);
  - проверить на iOS: не переключает ли активный микрофон звук
    `speechSynthesis` в разговорный динамик и не приглушает ли его.
